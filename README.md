# SignalSec — Cybersecurity News (Jekyll + GitHub Pages)

A responsive, editorial-style cybersecurity news website inspired by the structure of professional news sites, with original SignalSec branding. Built for GitHub Pages and Markdown-based publishing.

## What's included

- Responsive homepage with featured story and latest-post cards
- Reusable article layout and Jekyll post collection
- Category pages: vulnerabilities, data breaches, threat intelligence
- Search on the Latest page (client-side title/summary/category search)
- Dark-mode toggle (saved in the browser)
- RSS feed, sitemap and SEO tags through GitHub Pages-supported plugins
- Editorial sources and standards page
- Sample post marked as an editorial template

## Before publishing

1. `_config.yml` is already configured for `https://lazyowl-lab.github.io` with `baseurl: ""`, because this repository is published as a user site (`lazyowl-lab.github.io`). If you rename the repository or publish it as a project site, update `url` and `baseurl` accordingly.
2. Change the publication name, description and any contact/about copy to match your project.
3. Replace or remove the sample post `_posts/2026-10-27-welcome-to-signalsec.md`. It is clearly marked as a preview, not live reporting.
4. Review the source links and write your real editorial policy before launch.

## Publish with GitHub Pages

1. Create a GitHub repository (for example, `cybersecurity-news`).
2. Upload the contents of this project to the repository root.
3. Open **Settings → Pages**.
4. Under **Build and deployment**, choose **Deploy from a branch**.
5. Select your branch (usually `main`) and folder `/ (root)`, then save.
6. Wait for the Pages build to finish. Check the Actions tab if the build fails.

GitHub Pages supports Jekyll. The `github-pages` gem in the Gemfile is for local preview; GitHub Pages builds using its own supported environment.

## Preview locally (optional)

Install Ruby, Bundler and Git, then run:

```bash
bundle install
bundle exec jekyll serve
```

Open the local URL printed by Jekyll (typically `http://127.0.0.1:4000`). For a project repository, local preview uses the `baseurl` configured in `_config.yml`; change it temporarily if needed for your local setup.

## Publish a new article

Create a Markdown file in `_posts/` using this naming format:

`_posts/YYYY-MM-DD-short-article-title.md`

Example front matter:

```yaml
---
title: "A clear, specific headline"
date: 2026-10-28 09:30:00 +0200
categories: [vulnerabilities]
tags: [CVE, patch]
description: "A short, factual summary of the story."
author: "Your Name"
---
```

Write the article below the second `---`. Use original wording, link primary sources and state what is known versus unconfirmed. The homepage and Latest page will list posts automatically.

Supported category values used by the included category pages:
- `vulnerabilities`
- `data-breaches`
- `threat-intelligence`
- `security-research`

A post can have more than one category, for example `categories: [vulnerabilities, security-research]`.

## Hybrid news workflow

GitHub Pages is static hosting and does not run a background news scraper or server-side application. This starter therefore supports:
- **Original articles:** write and publish Markdown posts.
- **Curated external news:** research an external story, then publish your own summary with attribution and a link to the original report.

The Sources page links to useful starting points. External links are not automatically imported as article posts; that should be a separate feed/aggregation feature if you decide to add one later. Do not republish other publishers' full text or images without permission.
